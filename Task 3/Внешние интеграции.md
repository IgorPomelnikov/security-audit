# Список требований к внешним интеграциям

## 1. Требования к безопасности

### 1.1 Сетевая безопасность
- Взаимодействие с внешними системами осуществляется исключительно через корпоративный сетевой экран (firewall)
- Разрешенные IP-адреса и домены должны быть согласованы и внесены в белый список
- Все соединения должны использовать шифрование TLS 1.2+ для защиты передаваемых данных

### 1.2 Обработка персональных данных
- Персональные данные должны подвергаться токенизации или хешированию перед передачей
- Биометрические данные не покидают внутренний защищенный контур системы
- Номера автомобилей передаются в виде криптографических хешей (с солью)
- Идентификаторы пользователей заменяются на уникальные токены при взаимодействии с внешними системами

### 1.3 Доступ к устройствам
- Пользователи получают доступ к устройствам (домофонам, шлагбаумам) только через централизованную авторизацию
- Список доступных устройств предоставляется партнерским сервисом через API
- Привязка устройств к аккаунту пользователя происходит через безопасный выбор из разрешенного списка

## 2. Протоколы аутентификации и авторизации

### 2.1 Межсистемная аутентификация
- **Основной протокол**: OAuth 2.0
- **Точка авторизации**: выделенный сервис Keycloak в DMZ-зоне
- **Срок жизни токена**: не более 5 минут (оптимизировано для операций с домофонами и шлагбаумами)

### 2.2 Взаимная аутентификация с партнерами
- Регистрация сервиса в партнерской системе через OAuth 2.0
- Обмен идентификаторами пользователей в токенизированной форме
- Верификация подлинности запросов через механизм подписей или JWT

## 3. Организация взаимодействия между системами

1. **Инициализация**: 
   - Пользователь выбирает устройство из списка, полученного от партнера
   - Система отправляет токенизированный ID пользователя партнерскому сервису

2. **Конфигурация**:
   - Пользователь добавляет данные (номера автомобилей, биометрию)
   - Хешированные данные отправляются в соответствующие сервисы

3. **Эксплуатация**:
   - Партнерский сервис отправляет хеш для верификации
   - Система проверяет соответствие и инициирует действие (открытие двери/шлагбаума)
   - Ответ выполняется в рамках 5-минутного окна токена

### Ограничения и гарантии
- Время жизни токена соответствует времени типичной операции
- Все интеграции работают по принципу "need-to-know"
- Отсутствие прямой передачи персональных данных между системами
- Аудит всех операций взаимодействия с внешними системами
